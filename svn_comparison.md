# Git и SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто файл-указатель (41 байт) на коммит. Создание ветки происходит
локально и мгновенно, файлы не копируются, а переключение меняет только рабочую копию.
В SVN ветка — это копия каталога в центральном репозитории (`svn copy trunk branches/x`):
операция выполняется на сервере, требует сети, а слияние веток исторически было ручным
и сложным, поэтому ветки в SVN создают редко.

## 2. Можно ли в SVN сделать коммит без интернета?
Нет. В SVN коммит сразу записывается в центральный репозиторий, поэтому нужен доступ к серверу
(интернет или локальная сеть). Без связи можно только редактировать файлы и смотреть `svn diff`
относительно последней полученной версии. В Git коммит локальный — push можно сделать позже.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Legacy-проекты (банки, госсектор), где миграция истории и процессов дороже пользы.
- Большие бинарные файлы (игровые ассеты, CAD-модели): SVN умеет блокировать файл (lock)
  и позволяет выкачать только нужный подкаталог, а не весь репозиторий.
- Когда нужны строгие права доступа на отдельные каталоги и единый центральный контроль.
